#### Key Architectural Decisions

**Decision: Default profile starts in `SUGGESTIONS_ONLY` mode**
- Rationale: Even PRO users should explicitly opt into autonomous execution for trust/safety.
- Impact: Tests must explicitly set `ExecutionMode.AUTONOMOUS` to test rule execution.
- Future: Onboarding should prompt user to select execution mode during setup.

**Decision: FREE tier gets `basic_automation` (notifications only, no system changes)**
- Rationale: Ethical boundary — core mental health awareness should never be paywalled.
- Impact: `SystemAutomationEngine.trigger()` returns `"suggested"` status for FREE users even if rules match.
- Future: Consider showing an upsell banner when FREE users receive suggestions: "Adaptive noticed you're low energy. Upgrade to Pro to auto-dim your screen."

**Decision: `system_actions` is a separate feature from `autonomous_mode`**
- Rationale: Allows for "ask-first" mode (PRO) where system changes happen but only after user confirmation.
- Impact: `_can_execute_system_actions` gates the actual `_execute_action()` method. `_can_use_autonomous_mode` gates whether rules fire automatically vs. returning `"pending_confirmation"`.
- Future: Could add "scheduled actions" feature that doesn't require autonomous mode but still executes system changes.

**Decision: Custom rules are PREMIUM-only**
- Rationale: Custom rule builder is a power-user feature that requires understanding of triggers/actions. Default rules cover 95% of use cases.
- Impact: `_effective_rules()` only includes `profile.custom_rules` if `_can_use_custom_rules` is true.
- Future: Could allow 1-2 custom rules on PRO as a trial/upsell mechanism.

**Decision: Analytics are PREMIUM-only**
- Rationale: Analytics require sustained data collection and are most valuable to power users tracking long-term trends.
- Impact: `get_analytics()` returns `None` for FREE/PRO. Events are not recorded.
- Future: Could show basic "total focus hours" counter on PRO as a teaser.

## Technical Details for Next Developer

### How Tier Gating Works

The `SystemAutomationEngine` checks subscription tier at multiple decision points:

1. **`_effective_execution_mode()`** — Respects profile setting but caps at tier limit:
   - FREE → always `SUGGESTIONS_ONLY`
   - PRO → `SUGGESTIONS_ONLY` or `ASK_FIRST` or `AUTONOMOUS`
   - PREMIUM → same as PRO

2. **`trigger()`** — Routes based on execution mode:
   - `SUGGESTIONS_ONLY` → returns `"suggested"` status, no actions executed
   - `ASK_FIRST` → returns `"pending_confirmation"` status
   - `AUTONOMOUS` → executes actions via `_execute_action()`

3. **`_execute_action()`** — First line checks `_can_execute_system_actions`:
   - FREE → returns `{"status": "gated", "detail": "Requires PRO subscription"}`
   - PRO/PREMIUM → executes actual system command via `PlatformBackend`

4. **`_effective_rules()`** — Builds rule set:
   - Base: `get_default_rules()` (14 rules, all tiers)
   - PREMIUM only: adds `profile.custom_rules` if enabled in profile

5. **`_check_scheduled_blocks()`** — Only runs if `_can_use_scheduled_blocks` (PREMIUM)

6. **`get_analytics()`** — Returns `None` unless `_can_use_analytics` (PREMIUM)

### Testing Pattern

All automation tests must inject `StubBackend()` and a `MockSubscriptionManager`:

```python
class MockSubscriptionManager(SubscriptionManager):
    def __init__(self, tier=SubscriptionTier.PRO):
        self._tier = tier
        super().__init__()
    @property
    def current_tier(self): return self._tier
    def has_feature(self, feature):
        return feature in FEATURES_BY_TIER.get(self._tier, set())

# In test:
engine = SystemAutomationEngine(
    data_dir=tmp_path,
    backend=StubBackend(),
    subscription_manager=MockSubscriptionManager(SubscriptionTier.PRO),
)
engine.config.set_execution_mode("default", ExecutionMode.AUTONOMOUS)
```

**CRITICAL:** Do NOT rely on `get_backend()` in tests on macOS. It returns `MacOSBackend` which executes real AppleScript (`osascript`, `defaults write`, `killall`). This caused sandbox isolation issues in prior sessions. Always inject `StubBackend()`.

### Data Persistence

Automation config and analytics are stored in `~/.mindful_optimizer/`:
- `automation_config.json` — profiles, execution modes, custom rules, scheduled blocks
- `automation_analytics.json` — rule stats, daily summaries, focus trends

Both use JSON with `json.dump(..., default=str)` for datetime serialization.

### GUI Integration

The `AutomationWidget` is added as a tab in `main_window.py`. It receives:
- `automation_engine` (lazy-loaded `SystemAutomationEngine`)
- `subscription_manager` (lazy-loaded `SubscriptionManager`)

The widget is **always visible** (not gated behind a tab) because the free tier can view rules and see suggestions. Upsell messaging appears inline within the widget for gated features.

## Context That Might Not Be Obvious

### Why `SubscriptionManager` Uses Hardcoded Secret
The `SubscriptionManager._SECRET = b"mindful-organizer-offline-license-v1"` is documented as suitable only for offline demonstration and early beta. If this product scales, this MUST be replaced with asymmetric crypto (Ed25519), per-build secret injection, or server-side API validation.

### Why Tests Use `MockSubscriptionManager` Instead of Real One
The real `SubscriptionManager` reads from `~/.mindful_optimizer/license.json`. On a developer machine, this might contain a real trial or license that returns PREMIUM, causing tests to behave differently across machines. The mock ensures deterministic tier behavior.

### Why `automation_widget.py` Has No GUI Tests
PyQt6 GUI testing is excluded from CI (`-m "not gui"`). The widget was designed defensively: all tier checks use `subscription_manager.has_feature()` which is thoroughly unit-tested. The widget itself is a thin presentation layer.

### The "Desktop Moat" Is Real
The business plan, brand strategy, and technical architecture all hinge on one fact: **mobile apps and web apps cannot access system APIs** (kill processes, change brightness, toggle DND, reorganize files). This is not a marketing claim — it is enforced by iOS sandboxing, Android permissions, and browser security models. As long as Adaptive stays desktop-native, no mobile competitor can replicate the core value proposition.

### The Ethical Boundary Is Enforced in Code
The subscription gating explicitly keeps core mental health tools (tracking, crisis plan, breathing, journaling, medication) in the FREE tier. This is not just a business decision documented in the plan — it is enforced by `FEATURES_BY_TIER` in `subscription_manager.py` and by the `_can_execute_system_actions` check in `system_automation.py`.
